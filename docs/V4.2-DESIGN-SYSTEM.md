# V4.2 设计规范

## 方向

沉静、清晰、有温度、可信、轻量、结果优先。背景使用冷灰，内容面板使用白色；靛青表示主操作，绿/琥珀/红/蓝分别表达成功、注意、危险和信息。

## Token

- 原始 Token：`src/design/tokens.css`，包括颜色、间距、圆角、阴影、动画和应用布局。
- 语义 Token：`src/design/semantic.css`，页面和组件只能依赖 `--background`、`--surface`、`--foreground`、`--muted-foreground`、`--primary`、`--success`、`--warning`、`--danger` 等语义值。
- 深色 Token 已预留；V4.2 只验收浅色模式。
- `prefers-reduced-motion` 会关闭非必要动画，所有可交互元素都有统一 `focus-visible` 样式。

## 组件层级

1. `ui`：Button、Card、Skeleton 等无业务语义组件。
2. `feedback`：Loading、Empty、Error、Toast、ConfirmActionDialog。
3. `layout`：PageHeader、FilterBar、ContextPanel、DetailDrawer。
4. `domain`：StatusBadge、AutomationCard、ConfirmationCard、ResultSummaryCard、ConnectionHealthCard、SuggestionCard、ExecutionTimeline。

同一状态必须经 `src/domain/status.ts` 映射，页面不自行发明状态颜色或文案。领域组件不直接请求 API；页面负责调用和局部刷新。

## 交互规则

- 保存、运行、暂停、恢复、确认、拒绝、删除、诊断和重试使用独立 action key 防止重复提交。
- API 失败使用 `ErrorState`，没有业务数据使用 `EmptyState`，二者不可混用。
- 高风险和不可撤销操作使用 `ConfirmActionDialog`；详情使用 `DetailDrawer`。
- Dialog/Drawer 必须有可读标题和描述，支持 Esc、焦点锁定和关闭后的焦点恢复。
- 图标按钮必须提供可访问名称；状态不能只靠颜色表达。
- 360px 使用导航抽屉；桌面侧栏可折叠。内容容器不得产生页面级横向滚动。

## 参考实现

V4.2 借鉴了 [shadcn-vue](https://github.com/unovue/shadcn-vue) 的可控组件组合方式，以及 [AI Elements Vue](https://github.com/vuepont/ai-elements-vue) 的 Conversation/PromptInput 语义。实现保留在本仓库内，未引入整套后台模板或第二套视觉体系。
